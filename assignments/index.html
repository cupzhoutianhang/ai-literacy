公开提交说明

GitHub 提交需要登录账号。姓名或教师认可的课堂代号、成果、附件与分数公开可见；请勿填写身份证、电话、账号密钥或未公开生产资料。这里的附件均为教学合成数据。

SUBMIT / REVISE / VERIFY

从完成到提交

01 / 准备成果

下载并填写模板

用豆包工作读取附件，生成题目要求的结果。保留 first_prompt 与 revision_prompt 两条提示词，每条至少 30 个非空白字符。再核对单位、缺失值或引用。

02 / GitHub 提交

粘贴完整 JSON

点击本题“提交作业”，登录 GitHub，填姓名或课堂代号、班级，粘贴完整 JSON。可另外拖入截图、Word、表格或 ZIP，供教师复核。

03 / 检查与修订

在原提交里改进

提交后等待 Actions 完成检查，分数和逐项反馈会回复在 Issue 下。修改时编辑原 Issue 正文，不把新版答案放在评论里。保存后自动重评。

自动分数代表什么？

八项成果检查各 10 分，共 80 分；两条提示词记录的完整性各 10 分，共 20 分。过程分只检查记录是否足够完整，不证明使用了豆包工作，也不评价提示词、报告或 Skill 的文字质量。自动检查规则公开，适用于形成性练习；教师可结合附件与过程证据复核。

格式错误会标记“需修正”，不直接记为零分。同一 GitHub 账号、同一任务按最后一次提交汇总；修改成果后需要重新评分。若设置了截止日期，迟交会单独标记，是否扣分由教师决定。

提交前做一次 JSON 格式预检

预检在你的浏览器内完成，不上传内容，也不生成正式成绩。最终分数以 GitHub 自动反馈或教师复核为准。

SUBMISSIONS & FEEDBACK

找到你的成绩记录

每次提交都有自己的记录页

在 Issue 中查看逐项分数、修改历史与教师反馈。账号来自 GitHub 登录身份；填写的姓名或课堂代号由教师核对。

所有课程提交 ↗检查运行状态 ↗

如果暂时没有自动回复，先检查工作流状态；也可在原 Issue 中请教师协助。

FOR INSTRUCTORS

教师管理与导出

管理操作需要仓库写入权限

发布题目与附件

在 GitHub 上传附件、模板，维护任务目录与评分检查项，再运行发布工作流生成提交表单。每次发布先保存恢复标签。

阅读出题与发布说明 ↗

复核或重新评分

打开评分工作流，点击 Run workflow，填写提交编号。需要改分时填写 0–100 的分数与原因；记录会保留自动分、教师分和复核说明。

进入评分与复核 ↗

导出班级成绩

运行导出工作流，完成后下载成绩包，含最新成绩、全部提交 CSV，以及双工作表 Excel。教师测试会被排除，未评分的新提交会明确标记。

生成并下载成绩包 ↗

下载包保留 30 天；成绩原始记录持续保存在 course-grades 分支，可再次生成导出。缺交名单需与你自己的学生名册核对。
